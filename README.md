# 词不溜 WordEcho

一个**完全离线**的安卓背单词 App：App 念英文单词 → 你口述中文意思 → 自动判对错 → 答错自动进错题本。  
外加：拍照识别手写单词纸、考研词库、语音指令、听筒模式。

> 这套工程是按你给的 11 步需求逐条落地写的，Kotlin + Jetpack Compose + Room，单模块，无 Hilt，方便你自己改。

### v0.22.0：发音换成端侧 Kokoro

系统 TTS 念英文难听，根因是多数国产 ROM 根本没装英文语音包，只能用中文引擎硬读。
换成一个真正会读英语的模型，并且**读任意单词**——不是预先算好一批音频。

- **引擎可选**：设置 → 发音引擎 → 系统朗读 / Kokoro 神经网络。默认仍是系统朗读，APK 体积不变
- **模型不塞进安装包**：82 MB，第一次打开开关时下载，支持断点续传（模型放 `filesDir/kokoro/`）
- **读任意词，包括你自己导入的**：内置 17.8 万词音素表（`assets/kokoro/lex.txt`），
  内置 430 词命中 100%，查不到的词自动退回系统朗读，不会变哑
- **音色跟随英式/美式**：美式 af_heart、英式 bf_emma
- **磁盘缓存 + 预取**：进答题时后台把这一轮的词先合成好，同一个词第二次是直接读缓存、0 延迟
- 合成链路纯 ONNX，不需要 NDK 编译（Piper 那条路要编 espeak-ng，刻意避开）
- 设置页新增诊断：「系统英文语音包 已安装 / 未检测到」，直接告诉用户口音怪的原因

为什么不做「预生成音频打进 APK」：词库是用户自己导入的，今天加的词明天就要能读，
预生成永远追不上；而且 430 词以外全哑，等于把一个可选功能做成了半成品。

### v0.21.1：看答案 = 记错

以前点「看答案」只是把释义展开给你看，流程照旧：看了答案再念一遍，甚至重听一遍再答，都能判对。
等于留了一条绕过去的路。

- **「看答案」直接按答错处理**：计入已答、写进错题本、艾宾浩斯复习等级回退，并立刻停麦
  （不停麦的话，看着答案念一遍就能骗过识别）
- 结果页写明「看了答案，记为不会。这个词下次还会出现」，停留 3.5 秒
  （比答错的 2.4 秒长，够看完释义再扫一眼笔记和形近词）
- **「跳过」同样记错**——不然点「跳过」就把上面这条绕过去了，改了半天等于没改
- 结果页里「看答案 / 跳过」置灰，防止重复计数

### v0.21.0：每日词库能按日期找了

批次攒到几十上百条，一路往下滑找某一天太费劲。

- 每日词库顶部、全部词库下面新增 **「查找日期」**：点开日历选一天，列表就只剩那天的上传
- 查找态下标题栏显示「正在查看 10 月 25 日」，卡片上显示「N 次上传 · M 个词」，点 **清除** 回到全部
- 选的日期没传过，不会给你一个空白页发呆，直接提示「X 月 X 日 还没有上传过单词」+ 一键看全部
- 同一天传了好几次时，几次都留着（本来就该这样）
- 日历**不允许选未来**（未来不可能有上传记录），默认停在今天或当前查找的那天
- 筛选逻辑抽成纯函数 `groupBatches()`，5 个单测盯住：分组顺序、只留当天、同日多批、
  空结果、以及 `2026-10-2` 这种不完整的日期串不会误命中
- 长按改日期和查找日期共用同一个日历弹窗，不会再出现两套不一样的行为

### v0.20.0：补传 —— 导入能指定日期了

以前的坑：25 号忘了传，26 号才补上传，词就全落进「今天」那一栏，
每日词库的日期永远缺一块，而且没法改。

- **导入页顶部新增「存入哪一天」**：默认今天，点「改日期」调到任意一天。
  10 月 25 号忘了传，26 号补的时候把日期调回 25 号，这批词直接进 25 号的每日词库
- **已经传过的批次也能改**：每日词库 → 长按某一批 → 「改日期」→ 选日期，整批挪过去
- 改日期只动归属日期，**错题记录、艾宾浩斯复习等级、笔记一个都不动**
- 老数据（`batchId = 0`、早期没有批次号的那批）挪动时自动补一个当天中午的批次号，
  不会因为主键撞车和别的 0 号批次被合并成一批
- 实现上 `batch_words` 是「先复制到新日期、再删旧的」（主键含 `batchDate`，
  直接 UPDATE 主键字段容易撞键），`words` 表上的冗余日期字段同步更新
- 顺带补齐了 v0.19.0 那条：粘贴导入解析出来的每一条都能直接改**单词拼写**和**释义**，
  改完单词会自动回词库比对补释义（不覆盖你手填的）

### v0.9.0：手写识别换引擎（Tesseract → ML Kit）

用户反馈「手写导入识别太差了，基本没识别对几个字」。这不是参数问题，
是**选错了引擎**：Tesseract 是为印刷体训练的，对手写体基本不可用。

- 新增 `ocr/MlKitOcr.kt`，用 ML Kit Latin 模型（模型随 APK 分发，
  `assets/mlkit-google-ocr-models/`，**不依赖 Google 服务，纯离线**）
- 设置里可切换「ML Kit（推荐）/ Tesseract」，默认 ML Kit
- 裁掉 x86/x86_64 原生库（`abiFilters`），APK 从 160MB 压回 104MB

同时修了两个语音相关的真问题：

- **Vosk 长句被切碎**：以前每检测到一句结束就 `onFinal`，App 收到第一段就判分，
  说「就是放弃的意思」只用到前两个字。改成**累积片段 + 静音 1.1 秒才提交**
- **一直没声音时死等**：加 7 秒无输入提示，告诉用户去查权限或换引擎

另外加了 DeepSeek 判分（可选，设置里填 Key）：本地规则拿不准的答案才调 API，
省钱；注意 **DeepSeek 官方 API 是纯文本的，做不了图片识别**。

### 关于「没有真机验证」这件事

尝试过装模拟器，结论是**这台机器跑不了**：

| 尝试 | 结果 |
|---|---|
| Android 14 x86_64 + 软件模拟（TCG） | QEMU 段错误退出（exit 139）：镜像要求 AVX，TCG 不支持 |
| Android 10 x86 + 软件模拟 | 同样段错误 |
| 装 AEHD 硬件加速驱动 | 沙箱安全策略屏蔽 `sc.exe`，内核驱动无法注册 |
| 开 WHPX | 需要重启系统 |

于是改用两条替代路线验证：

1. **JVM 单元测试**（`app/src/test/`）—— 判分 14 例、复习排期 8 例，覆盖同义词替换、词性剥离、拼写容错、等级封顶、边界夹取。
2. **Robolectric 真实渲染**（`ScreenRenderTest`）—— 起 Activity → `setContent` → 把 DecorView 直接 `draw` 到 Bitmap，产出 5 张 PNG。能验证布局是否崩、文字是否溢出、配色与间距；验证不了触摸、音频、真实设备字体。

这套测试直接抓到并修掉 3 个真问题：

- **没有 TTS 引擎时，背诵永久卡在「正在朗读」** → 加两个看门狗（1.5s 未出声放行 + 总时长上限兜底）
- **首次安装后立刻背诵会误报「词库为空」** → 背诵前先 `join` 种子词库灌入任务
- **背诵页题面顶在上边、中间一大片空白** → 上下各加一个 weight，题面垂直居中

### v0.4.0 新增：学习曲线 + 形近词跳转

### v0.3.0 新增：笔记 / 形近词 + 模型导入

**笔记 / 形近词**

- 单词表点任意一行 → 展开编辑器，填「笔记 / 记忆口诀」和「形近词（逗号分隔）」
- 折叠状态下有笔记的词会显示一行蓝色小字，扫一眼就知道记过什么

**模型导入（解决"怎么把 42MB 模型弄到手机上"）**

- Tesseract 语言包支持 zip 或单个 `.traineddata`
- 导入成功后立刻生效（会主动释放已加载的旧模型），**不用重新编译**

### v0.2.0 新增：艾宾浩斯复习

- 每个词带一个 0~8 级的记忆等级，答对升一级、答错打回 0 级
- 间隔：5 分钟 → 30 分钟 → 12 小时 → 1 天 → 2 天 → 4 天 → 7 天 → 15 天 → 30 天
- 首页出现「复习到期的 N 个词」，点进去只出到期的词，清完显示「今天的复习都清完了」
- 混合模式里，到期的词会被额外提权 ×1.5，不用等它掉进复习队列才想起
- 单词表每行会显示「复习：2 天后」

## 一、5 分钟跑起来

1. **用 Android Studio 打开** `WordEcho/` 目录（File → Open）。  
   首次同步会自己下载 Gradle 8.7 和依赖，等它转完。
2. **放两个模型文件**（不放也能跑，只是对应功能会降级，见第三节）：
   - `app/src/main/assets/tessdata/eng.traineddata` ← 手写 OCR
   - `app/src/main/assets/vosk-cn/` ← 中文离线语音识别（整个模型目录内容）
3. 手机开 USB 调试，点 **Run ▶**。  
   首次启动会问录音权限，允许。
4. 点「开始背诵」。

**没有任何模型时**：App 会提示「语音模型未就绪」并自动切到键盘作答，主流程照样能测通。

## 三、模型清单（两种放法，任选其一）

| 文件                            | 大小                          | 作用               |
| ----------------------------- | --------------------------- | ---------------- |
| `eng.traineddata`             | 4 MB（fast）/ 23 MB（standard） | 手写 OCR           |
| `vosk-model-small-cn-0.22`    | 42 MB                       | 中文语音识别（主模式必需）    |
| `vosk-model-small-en-us-0.15` | 40 MB                       | 英文语音识别（「中→英」模式用） |

**放法 A：App 内导入（推荐，不用重新编译）**

1. 电脑下载模型 zip
2. 用 USB / 微信文件传输 / QQ 把 zip 传到手机
3. App → 设置 → 离线模型 → 点对应按钮 → 选那个 zip

**放法 B：塞进 assets 再编译**

- `eng.traineddata` → `app/src/main/assets/tessdata/`
- Vosk 中文模型解压后的 `am/ conf/ graph/` → `app/src/main/assets/vosk-cn/`
- Vosk 英文模型 → `app/src/main/assets/vosk-en/`

两种放法效果一样，A 不用重新编译、B 可以随 APK 分发。全塞进去 APK 大概 **160 MB**。

下载地址见各 assets 目录里的 `PUT_*.txt`。

## 四、需求 → 代码对照表

| ⑤ 语音指令             | `speech/VoiceCommand.kt`                      | 「再说一遍 / 跳过 / 下一个 / 结束背诵」                                                 |
| ⑥ 3B 小模型           | `judge/LlmJudge.kt`                           | 已留好接口，**默认空实现**，见第八节                                                     |

## 五、判分是怎么做的（最容易被问的部分）

`FuzzyJudge` 完全本地、零算力，逻辑四层：

1. **切义项**：`"v. 放弃；抛弃；遗弃"` → `["放弃","抛弃","遗弃"]`（自动剥掉词性标记）
2. **逐项打分**：完全相等 1.0 → 包含 0.95 → 反向包含 0.55~0.92 → LCS 相似度
3. **同义词典**：20 组考研高频同义替换（放弃/抛弃/舍弃…），命中给 0.85
4. **阈值**：`≥0.62` 判对；`0.42~0.62` 判错但提示「很接近」，把标准释义显示出来

所以你说「抛弃」而词库写「放弃」也算对；说「就是放弃的意思」也能命中（前缀自动剥掉）。

## 八、接入 3B 小模型（第 6 步的后续）

代码里已经留好接缝，**现在不接也能用**：

```kotlin
// judge/LlmJudge.kt
interface LocalLlm {
    fun isLoaded(): Boolean
    fun judgeMeaning(answer: String, meaning: String): Boolean?
}
```

它只在「规则判分落在 0.15~0.9 模糊区间」时才被调用，模型只回答「算对 / 算错」，不自由生成，token 极短。

接 llama.cpp 的步骤：

1. `git submodule add https://github.com/ggerganov/llama.cpp`，用 NDK 编 `libllama.so`（arm64-v8a）
2. 写一个 `LlamaBridge` JNI：`loadModel(path)` / `eval(prompt): String`
3. 模型文件（如 Qwen2.5-3B-Instruct-Q4_K_M.gguf，约 2 GB）放 `filesDir`，**不要放 assets**（assets 不能 mmap，加载会炸内存）
4. 实现 `LocalLlm`，在 `AppContainer` 里把 `NoopLocalLlm` 换成它
5. 首次进入设置页时按需 `loadModel`，退出背诵 5 分钟后 `unload`，避免常驻内存

建议 prompt 就一句：  
`判断学生答案是否与标准释义意思一致，只输出 对/错。\n标准：{meaning}\n学生：{answer}`

## 九、已知限制（先说清楚，别踩坑）

1. **手写照片 OCR 没有 100% 的方案**。Tesseract 对工整手写尚可，潦草连笔会错。所以设计上把「标黄 + 一键改」当作核心环节，而不是可选项。想再准一档可以换 PaddleOCR（PP-OCRv4 检测+识别，模型约 10 MB，接入成本约 1 天）。
2. **TTS 依赖系统语音包**。部分国产 ROM 英文语音包要手动下载（设置 → 无障碍 → 文字转语音）。App 检测不到会回退英文引擎并提示。
3. **听筒模式不是所有机型都听话**。少数厂商 ROM 会忽略 `MODE_IN_COMMUNICATION`，表现为仍从扬声器出。这不是代码能解决的，只能换机型验证。
4. **词库只有 431 个词**。完整 5500 需要你自己导一份 tsv（网上公开词库很多），格式 `单词<Tab>释义`，一行一个，App 直接吃。
5. **Vosk 中文小模型对口音一般**。方言重的话建议换 `vosk-model-cn-0.22`（1.3 GB），代价是体积。
